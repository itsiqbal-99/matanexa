# Matanexa vNext — Evidence Contract

Status: implemented in Phase 3, 21 October 2026.

## Purpose

Evidence is a server-produced representation of an exact retrieved hadith record.
It is independent of any LLM provider and is the only future-safe source for
citation validation. A model response, citation string, or record ID is never
accepted as proof by itself.

## Fields

Each evidence item contains:

- `recordId`: stable PostgreSQL hadith UUID;
- `citationId`: opaque `cite_<uuid>` generated by the server for one execution
  session;
- `exactText.arabic` and `exactText.indonesian`: complete retrieved text, never an
  excerpt or model rewrite;
- reference metadata: collection, hadith number, numbering scheme, book, chapter,
  narrator, record URL, and verification URL;
- source metadata: source slug, display name, and source URL;
- provenance: source attribution, translation attribution, license name, and
  license URL;
- normalized status: verification, publication, and research-only marker;
- eligibility: active server policy, decision, and explicit reasons.

The Zod schema is exported from `@matanexa/contracts`. It is strict: missing or
extra fields, invalid URLs/UUIDs, empty exact text, and unknown statuses fail.

## Policy mapping

| Server data scope         | Record source                                | Evidence result                                 |
| ------------------------- | -------------------------------------------- | ----------------------------------------------- |
| `published`               | `published_hadiths`                          | verified + approved, public-eligible            |
| `published`               | research-only record from any faulty adapter | rejected fail-closed                            |
| `local_pilot` development | `local_pilot_hadiths`                        | explicitly research-only, never public-eligible |
| `mock`                    | placeholder repository                       | excluded; empty evidence                        |

The mapping does not alter database views or governance. Public eligibility still
comes from the existing `verified` + `approved` + non-simulation view boundary.

## Citation validation

Validation is session-scoped and fail-closed:

1. Only citation IDs previously issued by retrieval in the same private ledger are
   candidates.
2. Duplicate citation IDs are rejected.
3. The gateway re-fetches the record by stable UUID through the same corpus policy.
4. Record ID, exact Arabic/Indonesian text, reference URLs, verification status,
   source slug, number, and numbering scheme must match the ledger fingerprint.
5. Missing, changed, ineligible, research-only-in-public, or invented citations are
   rejected.

The ledger does not trust a caller-provided record-to-citation mapping. Citation
IDs are intentionally not stable across sessions; the hadith `recordId` is the
stable identity, while the citation ID is a capability scoped to one retrieval
execution.

## Integrity and output bounds

Exact text is not truncated to satisfy output bounds. If the complete result would
exceed the configured byte limit, execution fails with `OUTPUT_TOO_LARGE`. This
avoids silently turning partial text into purported exact evidence.

Phase 3 does not generate answers, persist evidence, log raw evidence by default,
or expose this contract through a new HTTP endpoint.
