# ADR-002 — Toolchain dan batas G0

- Status: Accepted, 16 Oktober 2026.
- Folder kit `D:\apps\matanexa` menjadi root monorepo; tidak membuat repository
  bersarang atau menggandakan dokumen source of truth.
- Node awal 26.8.1/npm 12.0.2 adalah lini Current. Node 24.22.0 Krypton LTS/npm
  11.19.1 dipakai untuk instalasi dan verifikasi. Arsip Windows resmi disimpan
  lokal di `.tools/` dan checksum SHA256 diverifikasi; instalasi global tetap.
- Next.js 16.4.2, NestJS 12.1.3, CLI Nest 12.0.8, Tailwind 4.3.3; TypeScript
  5.9.3 dipilih dalam rentang dukungan typescript-eslint 8.71.2 (<6.1), bukan
  TypeScript 7 terbaru yang belum cocok dengan linter. ESLint memakai lini 9.
- Satu `package-lock.json` root mengunci seluruh dependency transitif. `npm ci`
  mereproduksi instalasi. Paket utama dipin; dependency lain dibatasi major.
- Scaffold dibuat manual mengikuti dokumentasi resmi, tanpa file demo generator
  yang tidak diperlukan. Tailwind v4 memakai PostCSS dan `@import`, tanpa config
  v3. ESLint flat config, Prettier, tidak menggunakan `next lint`.
- `packages/contracts` belum diperlukan karena belum ada pertukaran DTO bisnis.
  Tidak memasang driver DB/provider AI sebelum gate yang membutuhkan.
- G0 hanya halaman fondasi dan health; mode selain mock ditolak secara eksplisit.
  `databaseConfigured: false` menyatakan integrasi DB belum aktif. G1–G6 tetap
  di luar pekerjaan ini. Root orchestrator menghentikan pasangan bila satu exit.
- Server hanya bind loopback. CORS hanya origin HTTP localhost eksplisit.
- Testing memakai runner bawaan Node + request HTTP nyata ke NestJS, tanpa
  framework tes tambahan atau model/akun eksternal.
- Audit instalasi awal menemukan advisory braces tanpa versi patch melalui
  `eslint-config-next`. Konfigurasi itu diganti flat config TypeScript + React
  Hooks + JSX accessibility agar rantai vulnerable tidak diperlukan. ESLint 9
  masih dipakai karena peer dependency JSX accessibility belum mendukung 10;
  peringatan deprecation dicatat sebagai keterbatasan toolchain.
