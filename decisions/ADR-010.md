# ADR-010 — Allowlisted retrieval tools and session-scoped evidence

- Status: Accepted, 21 October 2026. Authorized by the user's Phase 3 instruction.
- Context: the migration plan required retrieval gateway extraction, but Phase 3
  authorization additionally requires typed search/detail/related/validation tools,
  bounded execution, and evidence that can be validated independently of an LLM.
- Decision: use a static tool allowlist with strict Zod inputs, server-owned limits,
  request correlation, normalized errors, and a provider-neutral
  `RetrievalGateway`. The initial PostgreSQL adapter wraps existing search and detail
  behavior; it does not copy SQL or ranking policy.
- Evidence: each tool session owns a private ledger. Citation IDs are server-issued,
  opaque, and session-scoped. Validation requires ledger membership, a fresh lookup
  through the same policy boundary, and an exact evidence fingerprint match.
- Isolation: `published` policy rejects research records even if a faulty adapter
  returns one. `local_pilot` remains explicit development-only research evidence.
  Mock placeholders never become evidence.
- Related retrieval: supported only as an eligible seed plus a caller-supplied,
  validated query passed to existing search. No new keyword intent router or search
  engine is introduced.
- Consequence: a future orchestrator can use the same tools without importing
  PostgreSQL or Cloudflare implementations. Citations cannot be reused across
  execution sessions and oversized exact evidence fails rather than truncates.
- Rejected: dynamic function dispatch, arbitrary SQL, client-selected corpus scope,
  trusting model-created citation IDs, post-hoc citation guessing, and copying the
  lexical/hybrid/RRF implementation into a tool service.
