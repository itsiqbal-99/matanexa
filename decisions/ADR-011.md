# ADR-011 — Internal evidence-first conversational orchestration

- Status: Accepted, 21 October 2026. Authorized by the user's Phase 4 instruction.
- Context: the previous migration plan assigned Phase 4 to frontend/localStorage
  migration and a mock endpoint, while grounded orchestration was scheduled later.
  The new instruction explicitly replaces Phase 4 with backend-only orchestration
  and prohibits frontend/public AI changes.
- Decision: implement an internal NestJS orchestrator over `LlmProvider` and
  `RetrievalToolExecutor`, with no controller. Context and results remain provider
  independent. Current providers without native tools use retrieval-first planning;
  optional multi-turn query reformulation is bounded text, not function parsing.
- Native tools: only capability-verified models may receive static read-only tool
  definitions. Names and arguments are revalidated by the existing executor,
  execution count is bounded, and citation validation remains server-only.
- Evidence: temporary citation IDs stay inside one execution ledger. Conversation
  history carries stable record IDs only, which are re-fetched before reuse.
- Generation: no evidence means no generation. Invalid output/citation or provider
  failure produces evidence-only. Public policy rejects research evidence.
- Privacy: telemetry stores only bounded identifiers, outcomes, timings, counts,
  fallback codes, and numeric usage; no messages, evidence text, provider payload,
  or chain-of-thought.
- Consequence: the old Phase 4 frontend/localStorage work is deferred and the
  foundation portion of old Phase 5/6 is advanced. API/UI activation and streaming
  require a newly aligned future phase and explicit approval.
- Rejected: keyword intent routing, trusting client evidence/citations, arbitrary
  textual function execution, automatic cloud activation, new persistence/schema,
  public endpoint, and frontend changes in Phase 4.
