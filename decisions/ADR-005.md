# ADR-005 — G3 lexical intelligence

17 Oktober 2026. Implementasi G3 dilanjutkan sesuai permintaan pengguna yang
secara eksplisit mengizinkan fixture bila korpus nyata belum siap.

Gunakan komponen Nest DI untuk normalizer, analyzer, synonym service,
repository dan ranker. Query asli tetap dalam DTO/response; normalisasi hanya
salinan untuk retrieval. Hindari stemming dan edit-distance correction yang
tidak dievaluasi. Negasi tetap menjadi input frasa dan sinyal ranking.

Kamus TypeScript terstruktur memisahkan ekuivalen dari keterkaitan topik. Bobot
weak expansion lebih kecil, tanpa mengubah label topik database secara otomatis.
Ranking multi-sinyal dan dedup dijalankan PostgreSQL agar count/pagination tidak
berbeda dari hasil yang sudah disaring. Tidak menggunakan score derajat atau
menampilkan ranking internals pada UI.

Migration 003 hanya menambahkan topik yang dikurasi ke view publik; 001/002
yang terpasang tidak diedit. Filter verified+approved+non-simulation selalu
berlaku di Nest. Evaluasi CLI/tes menggunakan TEMP relation terpisah; tidak ada
parameter API untuk bypass view. Source/license approvals dan verifikasi
referensi tetap memerlukan bukti manusia.

G2 foundation dapat diverifikasi di Neon setelah kredensial tersedia, tetapi
corpus masih kosong saat audit. Jangan mengubah source kandidat menjadi
approved atau mempublikasikan fixture agar acceptance terlihat lulus.

64 judgment hanya mengukur topic retrieval pada fixture simulasi. Bandingkan
tiga profil bobot pada 48 query kalibrasi, laporkan 16 holdout, latency SQL,
no-result dan batas metrik secara jujur. Precision/recall produksi tetap
unavailable sampai dataset dan qrels berizin/verified tersedia. Tidak ada G4,
LLM, embedding, vector search, Redis, deployment atau layanan baru.

Kredensial yang sempat disalin pengguna ke .env.example telah dihapus dari
template setelah dipastikan salinannya ada pada .env yang diabaikan Git.

Prioritas G2.5 mendahului penutupan G3. Empat kandidat belum mempunyai bukti
izin memadai; gunakan fallback fixture eksplisit. Dry-run menjalankan pipeline
transaksi yang sama lalu ROLLBACK, tanpa bypass approval. Judgment simulasi
relevan/sebagian/tidak relevan dipisahkan dari legalitas dan verifikasi ilmiah.

Tes schema/TEMP memakai direct Neon karena transaction pooler tidak menyimpan
state sesi. API tetap pooled. Timeout koneksi 10 detik dipisahkan dari budget
SQL 5 detik setelah koneksi nyata terukur sekitar 6 detik. Benchmark menggunakan
SQL yang sama pada relasi TEMP, tanpa memasukkan fixture ke published_hadiths.
