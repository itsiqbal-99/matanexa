# ADR-013 — Phase 6 menjadi offline readiness dan semantic evaluation gate

- Status: Accepted, 21 Oktober 2026. Diotorisasi oleh instruksi Phase 6 pengguna.
- Context: roadmap awal menempatkan capability-aware tool loop pada Phase 6,
  tetapi Phase 4 sudah menerapkan capability check, static tool allowlist,
  validated arguments, bounded execution, deterministic non-tool path, evidence
  ledger, dan citation validation. Phase 5 menambahkan internal API dan buffered
  validated SSE. Mengulang loop akan menciptakan dua jalur orchestration.
- Decision: Phase 6 tidak membuat loop baru. Scope-nya direkonsiliasi menjadi
  provider readiness audit, deterministic offline evaluation dataset/runner,
  grounding hardening, model candidate plan, privacy/cost controls, dan explicit
  live evaluation approval gate.
- Evaluation boundary: hasil mock hanya membuktikan pipeline conformance. Ia tidak
  membuktikan kualitas bahasa Indonesia, reasoning, latency, token economics, atau
  stabilitas model nyata. Semua hasil tersebut tetap `NOT_EVALUATED` sampai live
  matrix diotorisasi dan dijalankan.
- Data boundary: fixture memakai placeholder eksplisit, bukan teks atau referensi
  hadits. Live contract probe hanya boleh memakai prompt sintetis. Research-only
  evidence tidak boleh dikirim ke external provider tanpa persetujuan data baru.
- Grounding: exact Arabic/translation dan status/grade tetap server-owned. Model
  output yang menyalin exact text, mengklaim grade, menghasilkan citation yang
  tidak dikenal, atau gagal strict result contract jatuh ke `evidence_only`.
- Live gate: model ID, privacy/data-processing approval, request/token ceiling,
  free-quota/cost approval, valid server credentials, synthetic-only data scope,
  dan explicit inference approval wajib tersedia bersamaan. Default tetap off.
- Consequence: tidak ada perubahan API v1, database, ranking, embedding, frontend,
  deployment, paid service, atau public AI. Phase 7 tidak dimulai.
- Rollback: hapus runner, fixture, scripts, dan test Phase 6; kembalikan tambahan
  output-policy validator jika diperlukan. Phase 1–5 tetap utuh tanpa migrasi data.
