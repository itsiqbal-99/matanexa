# ADR-008 — Capability-based AI provider ports

- Status: Accepted, 21 Oktober 2026. Disetujui pengguna sebelum Phase 1 dimulai.
- Context: `SearchService` dan indexer bergantung langsung pada
  `CloudflareEmbedding`; LLM provider belum ada. Provider/model berbeda tidak
  menjamin tool calling, streaming, JSON, usage, context, atau vector compatibility.
- Decision: orchestration bergantung pada `LlmProvider` dan
  `EmbeddingProvider` ports. Vendor REST/SDK behavior hanya ada di adapters.
  Capabilities diregistrasi per provider/model berdasarkan documentation/probe,
  unknown berarti unsupported.
- Initial adapters: existing Cloudflare BGE-M3 behavior, mock embedding, dan mock
  LLM. Hosted LLM adapter/model dipilih setelah approval dan capability evidence.
- Fallback: embedding failure -> lexical; LLM failure -> evidence-only; no automatic
  cross-vendor fallback. Provider tanpa tools memakai deterministic retrieval-first;
  tanpa streaming memakai honest non-streaming response.
- Security: endpoint hanya admin-configured, SSRF-validated, secret backend-only.
- Rejected: provider SDK di domain, arbitrary user URL, menganggap seluruh
  OpenAI-compatible server identik, dan membuat semua future adapters sekarang.

## Phase 2 amendment — 21 Oktober 2026

Pengguna memperluas Phase 2 yang semula hanya mencakup port embedding. Phase 2
sekarang juga mengimplementasikan kontrak LLM, Cloudflare REST adapter,
deterministic mock, capability validation, normalized telemetry/error, dan static
endpoint policy untuk adapter OpenAI-compatible masa depan. Tidak ada endpoint
percakapan atau inference otomatis; provider LLM default tetap `disabled` dan model
tidak diberi default. Perluasan ini konsisten dengan decision di atas serta tidak
memulai orchestration Phase 5.
