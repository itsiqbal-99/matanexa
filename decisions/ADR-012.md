# ADR-012 — Fail-closed internal conversation API and validated SSE

- Status: Accepted, 21 October 2026. Authorized by the user's Phase 5 instruction.
- Context: Phase 4 completed provider-neutral grounded orchestration and part of
  the capability-aware tool loop that the earlier roadmap placed in Phase 5/6.
  There is still no HTTP conversation surface or streaming transport. The old
  Phase 7 proposed real SSE, but sending model deltas before evidence/citation
  validation would violate ADR-009.
- Decision: Phase 5 adds two stateless internal POST endpoints under
  `/api/v2/internal/conversations`: one JSON turn and one SSE turn. Both accept the
  same strict shared conversation request and call the existing orchestrator; they
  do not reimplement retrieval, provider, or citation logic.
- Access: endpoint registration is not treated as authorization. Runtime access is
  disabled by default, may be enabled only in development/test, and requires a
  backend-only high-entropy key compared in constant time. Disabled access is
  indistinguishable from a missing route. CORS is not an access-control boundary.
- Streaming: the public contract uses sequenced normalized events. Phase 5 emits
  orchestration status immediately, then buffers answer/reference content until
  the orchestrator has completed evidence and citation validation. Current
  `text_delta` events are explicitly marked `buffered_validated`; they are not
  claimed to be provider-native token streaming.
- Lifecycle: transport admission control, an overall request timeout, caller
  disconnect abort propagation, an SSE byte budget, and exactly one terminal event
  are enforced server-side. PostgreSQL cancellation remains best-effort at the
  caller boundary as documented in Phase 3/4.
- State: requests remain stateless. Stable hadith record IDs may occur only in
  assistant history and are revalidated by the existing orchestrator. Temporary
  citation IDs and evidence payloads are rejected as request fields.
- Privacy: SSE errors contain stable safe codes only. Raw provider events, prompts,
  responses, secrets, and chain-of-thought never cross the transport boundary.
- Consequence: Phase 5 advances the safe transport-contract portion of old Phase 7.
  Provider-native validated streaming and frontend consumption remain future work.
  The old Phase 6 tool-loop scope must be reconciled before further implementation
  because its foundation already exists in Phase 4.
- Rejected: public-by-default v2, CORS-only protection, query-string secrets,
  simulated typing presented as model streaming, unvalidated provider deltas,
  server conversation persistence, authentication/database schema work, and
  frontend changes in Phase 5.
